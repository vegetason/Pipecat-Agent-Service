1. Executive Summary

Intervue AI is an AI-powered interview simulation platform that helps job candidates prepare for real interviews by experiencing the closest possible replica of the real thing. Unlike generic interview prep tools, Intervue AI puts users under genuine pressure — serious AI interviewers, active proctoring, strict time constraints, and no second chances — so that when they face a real interview, they have already been there.

Mission	To make every candidate interview-ready by giving them a simulation so real, the actual interview feels familiar.

Core Philosophy	Real interviews are serious, pressured, and unforgiving. Our simulation must be too. A comfortable simulation produces a comfortable candidate who fails under real pressure.

Target User	Any individual preparing for a job interview — students, fresh graduates, experienced professionals, career switchers, and anyone returning to the job market.

What's New in v3.0	Emotion-Aware Adaptation, Weakness Pattern Memory, Ghost Mode, Pressure Multiplier, Rambling Detection, What-If Replay, Silent Mode. Backend migrated to Node.js.

2. Product Overview
2.1 What Is Intervue AI?
Intervue AI is a SaaS platform where users simulate real job interviews with an AI voice agent. The agent behaves like a real, serious interviewer — it does not forgive weak answers, it challenges vague responses, it follows up aggressively, and it maintains professional pressure throughout. After each simulation, users receive a comprehensive feedback report designed to help them understand exactly what they did wrong and how to improve.

4. System Architecture Overview
4.1 Service Separation
The platform is split into two distinct services that communicate over the network:

•	Node.js API Service — handles all business logic: auth, user profiles, simulation management, billing, evaluations, notifications, background jobs
•	Pipecat Agent Service — a Python microservice that handles the real-time voice pipeline only. It is spun up per simulation, talks to Claude, Deepgram, and ElevenLabs, and sends data back to Node.js

4.2 Communication Flow
Step	What Happens	Direction
1	User starts simulation via frontend	Browser → Node.js API
2	Node.js creates Daily.co room, fetches question bank, assembles context	Node.js → Daily.co API + PostgreSQL
3	Node.js spawns Pipecat agent subprocess / container with simulation context	Node.js → Pipecat Service
4	Pipecat agent joins Daily.co room and begins interview	Pipecat → Daily.co
5	Candidate joins the same Daily.co room	Browser → Daily.co
6	Live interview runs — Deepgram → Claude → Cartesia loop	Inside Pipecat
7	Pipecat sends transcript chunks in real time to Node.js	Pipecat → Node.js WebSocket
8	Pipecat sends emotion/stress scores to Node.js in real time	Pipecat → Node.js WebSocket
9	Interview ends — Pipecat sends full transcript + metadata to Node.js	Pipecat → Node.js HTTP POST
10	Node.js queues evaluation job via BullMQ	Node.js → Redis → BullMQ Worker
11	BullMQ worker calls Claude API to evaluate answers, generate report	BullMQ → Claude API
12	Results saved to PostgreSQL, user notified	Node.js → DB + Email

6. Realism & Pressure Features
6.1 The AI Interviewer — Serious by Design
Core Rule	The agent never rewards a bad answer. It never moves on from a weak answer without probing. It behaves exactly as a seasoned, professional interviewer would.

•	Agent never accepts vague answers — always probes for specifics and concrete examples
•	Agent pushes back on weak answers — challenges candidate to defend their position
•	Agent detects rehearsed, textbook answers and digs underneath them
•	Agent does not give hints or help — if candidate is stuck, silence is the response
•	Agent maintains professional tone — no warmth inflation to make candidate comfortable
•	Agent uses thinking pauses before responding — simulates real human processing time
•	Agent gives natural acknowledgements before moving to next question
•	Agent uses controlled follow-ups — maximum 2 per question, always on topic
•	Agent detects rambling and politely cuts the candidate off (see Section 6.6)
•	Agent handles interruptions naturally — just like a real interviewer would

6.2 Interviewer Personas
Persona	Style	Best For Practicing
The Corporate Executive	Formal, precise, zero tolerance for filler words, expects structured answers	Big 4, banks, Fortune 500
The Big Tech Engineer	Technical depth focus, asks follow-ups on every claim, expects specifics	FAANG, top tech companies
The Startup Founder	Fast-paced, informal but sharp, tests adaptability and hustle mindset	Startups, scale-ups
The Management Consultant	Structured thinking expected, case-style follow-ups, challenges logic	McKinsey, BCG, Bain
The Silent Type	Minimal reactions, long pauses, lets silence pressure the candidate	Stress tolerance training

Custom Persona	User defines a specific style for a target company or interviewer type	Company-specific prep

6.3 Proctoring as Psychological Pressure
Key Insight	Proctoring in Intervue AI is not about catching cheaters. It is about creating the psychological experience of being watched and evaluated — exactly as in a real interview. This pressure is the training.

•	Camera required — simulation cannot start without active camera feed
•	Explicit pre-simulation warning — user informed they are being monitored, just like a real interview
•	Face detection — alert if candidate leaves frame
•	Eye tracking — detects consistent off-screen gaze, flags as note-reading behavior
•	Tab switching detection — flagged and noted in post-simulation Integrity Report
•	Multiple faces detection — flags if another person enters the frame
•	Voice consistency monitoring — detects if a different voice is speaking
•	Background noise analysis — flags coaching or whispering
•	Phone detection — computer vision flags if candidate reads from a phone
•	All flags shown to candidate as self-awareness data in post-simulation Integrity Report
•	Proctoring Integrity Score shown alongside performance score

6.4 Time Pressure System
•	Every simulation has a strict time limit matching real interview durations — 30, 45, or 60 minutes
•	Visible countdown timer throughout the simulation
•	Per-question time limits — agent moves on if candidate takes too long
•	Time pressure warning — subtle visual cue when approaching question time limit
•	Hard mode — 20% shorter time limits for extreme pressure training
•	Time usage analysis in debrief — too slow, too fast, or well-paced per question

6.5 Pressure Multiplier — Dynamic Difficulty Escalation Mid-Simulation
Feature	The agent doesn't have fixed difficulty. It measures performance per question and escalates dynamically if the candidate is performing too well — exactly as real interviewers do when they sense strength.

•	State machine maintains a live pressure_score updated after every answer
•	If last answer score > 85%, agent injects an unplanned escalation challenge from a secondary question bank
•	Escalation types:
◦	Harder follow-up not originally in the question plan
◦	Mid-answer interruption — 'Let me stop you there. What is the core assumption you are making?'
◦	Edge case challenge — 'That works in ideal conditions. What if X failed?'
◦	Contradiction probe — 'You said X earlier. How does that square with what you just said?'
•	If candidate is struggling, difficulty stays flat — escalation only triggers on strong performance
•	Pressure Multiplier history shown in debrief — candidate sees exactly where difficulty was escalated and why
•	Implementation: state_machine/transitions.py — after each answer, compute pressure adjustment and optionally load escalation question from fallback bank

6.6 Rambling Detection & Intelligent Interruption
Feature	Real interviewers interrupt when they have heard enough. The agent does the same — but precisely, not randomly. A length + relevance model decides when to cut the candidate off politely.

•	processors/rambling_detector.py monitors token count and semantic repetition in real time
•	If rambling score exceeds threshold, an interrupt_frame is sent to the LLM
•	Agent interruption types:
◦	Polite cut-off: 'I think I got the point — let's move to the next question.'
◦	Reframe request: 'That was a bit abstract. Can you give me a concrete example?'
◦	Refocus: 'You mentioned X — can we stay focused on that specifically?'
•	Rambling flag included in post-simulation report with timestamp of each interruption
•	Semantic repetition detection — if candidate is saying the same thing in different words, agent flags it
•	Response length analysis — too brief, appropriate, or rambling scored per question

Feature	A simulation mode where the agent does not speak. Questions appear on screen. The user answers while being recorded. Feedback covers only non-verbal communication — isolating body language training from the cognitive load of listening.

•	Agent runs without TTS — no voice output at all
•	Questions displayed as text on screen with a per-question countdown timer
•	Proctoring and video analysis run fully — camera is the entire focus
•	LLM does not evaluate answer content in this mode — only non-verbal metrics are scored
•	Post-session report covers only: eye contact, posture, facial expressions, gestures, head movement
•	Ideal for candidates who want to isolate and fix body language without the pressure of responding to a voice
•	Implementation: modes/silent_mode.py — TTS pipeline disabled, display layer handles question rendering

7. Emotion-Aware Adaptation
Game Changer	Real interviewers pick up on nervousness. Some soften, some push harder. Our agent does the same — in real time, based on actual voice analysis. This is the feature that makes the simulation feel alive.

7.1 What It Does
The agent continuously analyzes the candidate's voice tone, pace, and micro-pauses to detect their emotional state. A stress_level score is computed in real time and injected into the LLM context as a dynamic modifier. The agent's behavior adapts based on this score — just like a real interviewer would adapt when they sense the candidate is struggling or breezing through.

7.2 Emotional States Detected
State Detected	Signal	Agent Behavior
High Stress / Anxiety	Fast pace, voice tremor, frequent micro-pauses, rising pitch	Agent softens slightly: 'Take your time, I will wait.' Reduces question complexity temporarily.
Over-Confidence	Very fast answers, minimal pauses, rehearsed cadence	Agent challenges harder: 'That sounds rehearsed. Give me a real example from your experience.'
Confusion	Long pauses, trailing sentences, rising intonation at end of statements	Agent rephrases the question once — and only once. Does not rephrase again.
Disengagement	Flat tone, very short answers, monotone delivery	Agent increases energy and directness to re-engage: 'Walk me through that in more detail.'
Recovered Calm	Stress drops after initial high — pace normalizes	Agent returns to standard pressure level naturally

7.3 Implementation
•	New file: processors/emotion_analyzer.py — Pipecat custom frame processor
•	Uses wav2vec2-emotion or Silero — small on-device model, no external API call, no added latency
•	Runs as a parallel processor in the Pipecat pipeline — does not block the main STT → LLM → TTS flow
•	Outputs a stress_level score (0.0 to 1.0) and emotion_tag (anxious, overconfident, confused, disengaged, calm)
•	context_builder.py modified to include candidate_stress_level and emotion_tag in every LLM prompt
•	Persona prompt gets a dynamic modifier appended based on current emotion state
•	Emotion timeline stored in DB per session — shown in post-simulation report as an emotional journey chart

7.4 Emotion Timeline in Debrief
•	Visual chart showing stress level across the entire interview duration
•	Annotated with which questions caused the most stress
•	Shows recovery patterns — how quickly candidate calmed down after a hard question
•	Correlated with performance — does stress correlate with weaker answers for this user?
•	Trend across simulations — is the user's baseline stress level decreasing over time?

8. Advanced Learning Features
8.1 Weakness Pattern Memory Across Sessions
Feature	The agent remembers across multiple simulations that you always ramble on 'Tell me about yourself' or always forget the STAR method. It proactively coaches you before the next simulation begins. No other tool does this.

•	Node.js backend tracks top 3 recurring weakness patterns per user across all simulations
•	Weakness patterns detected:
◦	Consistent rambling on specific question types
◦	Consistent failure to use STAR method on behavioral questions
◦	Consistent eye contact drops at specific moments
◦	Consistent filler word spikes on technical questions
◦	Consistent under-answering — too brief on important questions
•	Before each simulation, agent calls Node.js endpoint GET /api/v1/profile/weaknesses/ to fetch top patterns
•	Patterns injected into the agent's system prompt as pre-simulation reminders
•	Agent opens the simulation with a personalized coaching note:
◦	'Before we begin — last time you struggled with structuring your answers. Today I will prompt you with Situation, Task, Action, Result after each question.'
•	User can toggle this feature on or off — some users prefer to be tested cold
•	Weakness pattern history visible in user dashboard — shows which patterns are improving over time
•	Implementation: services/user_memory.py in Pipecat service, API endpoint in Node.js

8.2 Post-Simulation What-If Scenario Replay
Feature	After a simulation, the user can click on any answer and ask: 'What if I had answered differently?' The agent re-runs only that question with the new answer and shows how the follow-ups would have changed. Static recording becomes an interactive learning tool.

•	Available after every completed simulation — accessed from the Replay screen
•	User selects any question from the timeline
•	User types or speaks an alternate answer
•	System re-simulates only that single turn — using the stored context, persona, and difficulty
•	Returns how the agent would have followed up given the new answer
•	No full WebRTC session needed — runs as a stateless LLM call, returns text response
•	User can try multiple alternate answers for the same question — unlimited
•	Shows side-by-side: original answer + follow-up vs new answer + follow-up
•	Teaches users to understand the cause-and-effect of their answers on interviewer behavior
•	Implementation: POST /api/v1/sessions/:id/replay-question — Node.js endpoint that calls Claude with stored context

8.3 Ghost Mode — Interview the Perfect Version of Yourself
Feature	After a simulation, the platform creates an AI version of the candidate that answers the same questions perfectly. The candidate can hear those ideal answers spoken in their own voice. It is like shadowboxing with a perfect version of yourself.

•	Available after every completed simulation as an optional post-debrief experience
•	Node.js backend pre-generates ideal answers for every question using Claude — structured as the ideal version of the candidate's own style
•	A second LLM instance is loaded with a special prompt: 'You are this candidate's ideal self. Answer perfectly — confident, structured, concrete, using the STAR method where applicable.'
•	Ideal answers are spoken using the user's own cloned voice via ElevenLabs Voice Lab
•	User hears themselves — but better. Confident, structured, no filler words
•	Side-by-side mode: user's actual answer (audio) vs ghost ideal answer (audio) — played alternately
•	User can also read a transcript comparison alongside the audio
•	Voice cloning requires explicit upfront user consent — consent captured during onboarding and before first Ghost Mode use
•	Voice clone stored securely, used only for Ghost Mode within the platform
•	Implementation: modes/ghost_mode.py for agent, services/voice_cloning.py wrapping ElevenLabs Voice Lab API

15.2 Simulation State Machine
•	INITIALIZING — loading user profile, questions, persona, weakness memory, emotion analyzer
•	WAITING_ROOM — simulated wait 60-90 seconds before interviewer joins
•	INTRO — interviewer introduces themselves, delivers weakness memory coaching note if enabled
•	QUESTIONING — asking current question from pre-approved bank
•	LISTENING — processing answer, running emotion analysis and rambling detection in parallel
•	CHALLENGING — pushing back on weak or vague answer
•	FOLLOW_UP — probing deeper on current topic (max 2 per question)
•	ESCALATING — Pressure Multiplier triggered — injecting unplanned escalation challenge
•	TRANSITIONING — acknowledging answer, moving to next question naturally
•	WRAP_UP — closing simulation, fictional next steps
•	COMPLETED — sending full transcript, emotion timeline, and metadata to Node.js

20. Glossary

Term	Definition
Pipecat	Open-source Python framework for building real-time voice AI pipelines — used as a microservice
Node.js Backend	The main API server handling all business logic, auth, data, and job queues
BullMQ	Node.js-native job queue library backed by Redis — replaces Celery in this stack
Prisma	Type-safe ORM for Node.js used to interact with PostgreSQL
STT	Speech-to-Text — converts candidate speech to text for LLM processing
TTS	Text-to-Speech — converts LLM response text to spoken audio
LLM	Large Language Model — the AI brain powering the interviewer intelligence
Emotion Analyzer	On-device wav2vec2 or Silero model that detects stress and emotion from voice in real time
Stress Level	A 0.0-1.0 score output by the emotion analyzer, injected into the LLM prompt as context
Pressure Multiplier	Dynamic difficulty escalation system that makes the interview harder when the candidate performs too well
Rambling Detector	Pipecat processor that monitors token count and semantic repetition to decide when to interrupt
Ghost Mode	Post-simulation mode where the candidate hears ideal answers spoken in their own cloned voice
What-If Replay	Interactive post-simulation feature allowing candidate to re-run any question with an alternate answer
Silent Mode	Simulation mode with no agent voice — feedback covers body language only
Weakness Memory	Cross-session pattern tracking that injects personalized coaching into the agent before each simulation
Integrity Score	Proctoring metric showing how closely simulation conditions matched a real interview
STAR Method	Situation, Task, Action, Result — structured framework for behavioral interview answers
Question Bank	Pre-generated, approved set of questions loaded into the agent before simulation starts
Ghost Voice Clone	ElevenLabs-generated voice model based on the user's own voice — used only in Ghost Mode with consent
